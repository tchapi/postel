# Spike: webklex/php-imap against Dovecot

Date: 2026-10-23. Setup: `dev/mailserver` (docker-mailserver 15.1.0, Dovecot
2.3), one mailbox of 20,020 messages seeded with `app:dev:seed-mailbox`, the
fixture corpus in `backend/tests/Fixtures/mail`. Everything below ran on a
laptop over loopback, so absolute numbers are optimistic, relative ones hold.

## Questions

1. Does the master user login work, and what does a connection cost?
2. Can the message list be paged by date on a large mailbox with the webklex
   query builder?
3. Does webklex parse the ugly mails correctly?

## Findings

### Connection

- `user*master` login works out of the box with docker-mailserver's
  `dovecot-masters.cf`. Folders come back with SPECIAL-USE attributes.
- Connect + login + logout: 6 to 7 ms warm. Opening a connection per API
  request is fine.

### Paging with the webklex query builder: no

`$folder->query()->all()->fetchOrderDesc()->limit(50, $page)->get()` on 20k
messages:

- 243 IMAP commands per page, 211 of them `NOOP` (it pings the server before
  every command).
- Ordering is by UID, not by date: the first page was not the newest mail.
- It issues `UID STORE ... -FLAGS.SILENT (\Seen)` while listing. A read-only
  operation that writes flags is not something we want near a mailbox.
- Its response parser mangles `ENVELOPE` (quotes end up inside the fields),
  so the structured FETCH items are not usable either.

### Paging with raw commands: yes

Same mailbox, through `ImapProtocol::requestAndResponse`:

| Command | Time |
| --- | --- |
| `UID SORT (REVERSE ARRIVAL) UTF-8 ALL` | 35 ms |
| `UID SORT (REVERSE DATE) UTF-8 ALL` | 40 ms (211 ms cold, before Dovecot had cached the dates) |
| `UID SEARCH ALL` | 33 ms |
| `UID THREAD REFERENCES UTF-8 ALL` | 38 ms |
| `UID FETCH <50 uids> (FLAGS INTERNALDATE RFC822.SIZE BODY.PEEK[HEADER.FIELDS (...)])` | 1 ms |
| `UID FETCH <50 uids> (PREVIEW)` | 1 ms |

So a page of the list is one `UID SORT` plus one `UID FETCH`, about 40 ms on
20k messages, and Dovecot's `PREVIEW` extension gives us server-side snippets
for free. Threading is in the same ballpark when we want it.

The raw responses are easy to read when fetched with `$dontParse = true`. We
will write our own small FETCH response reader for the handful of items the
list needs, rather than rely on webklex's generic parser.

### Parsing messages

The fixture corpus through `Message::getHTMLBody()`, `getTextBody()` and
`getAttachments()`:

| Case | webklex 6.2 | zbateson/mail-mime-parser 4.0 |
| --- | --- | --- |
| Inline image with `cid:` | ok, content id exposed | ok |
| `format=flowed` | trailing spaces kept, `format` param lost | ok, param available |
| iCal invite | `text/calendar` as an attachment with a random name | part found, `method=REQUEST` readable |
| ISO-8859-1 body | converted to UTF-8 | converted to UTF-8 |
| RFC 2047 subject and From | **not decoded** (raw `=?iso-8859-1?Q?...`) | decoded |
| No `Content-Type` at all | ok | ok |
| Undeclared UTF-8 body | mojibake | mojibake (RFC says US-ASCII, both are right, we need a heuristic) |
| Outlook HTML | passed through | passed through |
| Nested mixed/alternative/related | 3 attachments, inline one with cid | same |
| `To` with a quoted comma, encoded `Cc` | `getTo()` returns a bare array, inconsistent API | parsed, names decoded |
| XSS mail | passed through (sanitizing is ours) | same |

Both parse the structure fine. webklex does not decode encoded words with
the default `utf-8` decoder (it expects `ext-imap`), and its API is uneven.
zbateson is a parser and nothing else, it handles headers properly and lets
us override a part's charset for the undeclared UTF-8 case.

## Decisions

- Keep `webklex/php-imap` as the IMAP transport only: connection, login,
  folders, `APPEND`, `STORE`, `MOVE`, `SEARCH`, and raw commands through
  `ImapProtocol`. Do not use its query builder or `Message` class.
- Message list: `UID SORT` + one `UID FETCH` with `FLAGS`, `INTERNALDATE`,
  `RFC822.SIZE`, `PREVIEW` and the header fields we display, read by our own
  response reader.
- Message rendering: fetch `BODY.PEEK[]`, parse with
  `zbateson/mail-mime-parser`, sanitize HTML ourselves. Treat an undeclared
  charset as UTF-8 when the bytes are valid UTF-8.
- Keep the fixture corpus as the test bed for the parser and the sanitizer,
  and grow it with every weird mail we meet.
